## 本批重复结构

以下结构在所选 3 个 case 中都出现，但只代表同一来源窗口内的局部模式：

1. 先写清待证明的信任边界，再定义保持不变的请求要素与唯一变量。
2. 使用适用的正控、固定负控和候选探针构成矩阵；状态码只作为观察值。
3. 用业务字段、权威归属映射或独立回读确认结果，不把请求回显当作生效。
4. 在执行前声明不变量、误报过滤、停止条件；有状态变化时声明精确回滚。
5. 首个最小真实影响闭合后停止扩大，结论限制在实际观察到的对象、字段和样本。

## 触发信号

- 同一路由可能接受不同身份材料，但缺少完整认证接受矩阵。
- UI 默认对象、全局选择器或可替换对象参数可能与服务端授权边界不一致。
- 正常 UI 只提交字段子集，服务端模型却暴露额外可写外观字段。
- 候选响应为 2xx、统一 success、空列表或请求回显，尚缺权威确认面。

## 决策规则

IF 候选涉及身份、对象或字段信任边界 AND 能建立健康基线、固定负控与单变量候选请求 THEN 先执行最小控制矩阵，并由权威读取面确认；BUT 任一关键不变量失败、负控与候选同形、或回滚不可证明时，不得升级为已确认结论。

## 常见转向点

- 缺失和固定无效材料与候选返回相同业务内容：转匿名公开、缓存或路由误分类。
- self 基线为空或账号健康失败：转 `blocked_need_material`，恢复后先重跑 self。
- 统一 success 或请求对象回显：转独立读取面，不继续扩大写入字段。
- 默认 UI 归属与权威映射冲突：先建立账号到对象映射，再做 cross 请求。

## 反复误报

- 离线解码令牌、客户端字段名或静态路由存在，不证明服务端接受和授权。
- HTTP 2xx/3xx、空列表或统一错误包，不证明越权读取或状态变化。
- 默认选择器、公共目录或共享对象，不等于目标主体外对象。
- 请求体被响应回显，不等于服务端持久化或业务逻辑已消费。

## 停止规则

- 首个非空受限样本或单字段独立回读形成稳定差分后停止同类扩张。
- 正控不健康、负控失效或无法维持单变量时停止并修复矩阵。
- 缺少第二账号、权威映射、可逆对象或读取面时记录材料与恢复后的第一步。
- 无法恢复精确前态时不执行状态变化。
