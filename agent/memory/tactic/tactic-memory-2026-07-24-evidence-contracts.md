## 稳定打法

1. 先定义待证明的信任边界，再选择同一路由或同一对象的最小变量。
2. 正控、负控和候选请求除一个变量外保持一致；HTTP 状态码只作为观察，不作为授权结论。
3. 身份类至少包含缺失材料、固定无效材料和受控主体；对象类先完成账号健康和非空 self 基线；写入类必须使用独立回读。
4. 结论只保留字段形状、类型、非空、长度、数量级和稳定差分，不保存可重放秘密或真实业务值。
5. 首个真实影响命中即停止扩大；有状态变化时恢复精确基线并复核没有残余差异。

## 适用前置条件

- 至少一个健康正控或明确说明正控材料为何不可得。
- 至少一个不会命中真实业务对象的固定负控。
- 候选与控制请求可保持单变量差分。
- 读取结论有非空受限字段，写入结论有独立权威回读。
- 已预先定义停止条件；有副作用时已定义可执行回滚。

## 转向信号

- 缺失和固定无效材料与候选返回相同业务内容：转匿名公开、缓存或路由误分类。
- self 基线为空或会话失效：转 `blocked_need_material`，不把 cross 空响应记作阴性。
- 接口只回显请求或统一 success：转独立读取面，不继续扩大字段。
- 默认 UI 选择器与权威对象归属冲突：转账号到对象映射，不把默认项当授权事实。

## 停止规则

- 首个非空受限对象、跨服务低权限样本或敏感字段回读命中后立即停止同类扩张。
- 无法维持正控健康、单变量差分或精确回滚时停止。
- 发现内容属于公开目录、共享范围或 requester self 时按误报归档。
- 需要第二账号、可逆对象、合法令牌或权威映射才能继续时，记录材料与恢复后的第一步。

## 证据要求

- 请求矩阵每个变体具有稳定 ID、认证别名、唯一变化和预期观察。
- 正负控与候选使用相同方法、路径、对象和非目标字段。
- 记录不变量是否满足；任一关键不变量失败时不得升级结论。
- 有状态变化时记录前态、后态、回滚方法和回滚复核。
- 来源通过匿名化与泄密扫描；`source_alias + relative_path` 构成稳定来源身份，SHA-256 只用于内容溯源，不参与独立案例计数。

## 可晋升规则

同批 pattern 继续保持 `draft`，不因被本 tactic 引用而自动升级；当前 tactic memory 保持 `active`。满足以下条件后才可提出正式 skill 评审：

- 每个根因家族至少再有 1 个独立任务 case，不共享同一任务来源。
- 至少跨 2 种技术实现保持相同前置、负控、不变量和停止规则。
- 新增样本未显示该矩阵会系统性漏报或鼓励不必要的数据读取。
- 晋升只由人工评审执行；`tool/promote_memory.py` 只能生成建议。

## 不应泛化的边界

- JWT 声明、UI 默认值和客户端对象字段都只是路由信号，不是漏洞事实。
- 服务端总数不等于实际读取行数；公开字段不等于受限字段。
- 单个受控写入命中不证明结算、权限消费或跨账号影响。
- 三个 case 的稳定来源身份均指向同一复盘索引和升级计划；即使这些文件内容变化、SHA-256 更新，也仍只算 1 组来源，因此不能据此标记为 `stable`。
