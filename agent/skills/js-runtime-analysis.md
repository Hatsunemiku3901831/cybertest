# JavaScript Runtime Analysis

本 skill 使用 `js.cdp` capability 观察运行时参数、调用栈、签名输入、SourceMap、Network 和受控 Hook。目标是建立客户端行为与服务端请求的可复现实验，不采集无关凭据，不把客户端逻辑直接等同于服务端漏洞。

## 路由条件

- 静态 JS 或 SourceMap 无法确定真实运行时参数。
- 签名、nonce、时间戳、序列化或加密输入需要单变量差分。
- 需要把 UI 动作、函数调用和网络请求关联到同一 `request_id`。
- 需要确认某字段来自用户输入、前端默认值、环境配置还是服务端返回。

先完成离线源码、chunk 和 SourceMap 分析；只有静态证据不足且 tactic 需要时才进入动态 Hook。

## 执行前门禁

- 读取 `dynamic-evidence.md` 和当前 tactic。
- 运行时确认 `js.cdp` 可用；只存在普通浏览器时使用声明的受限 fallback。
- 确认页面、账号、环境和测试对象均为受控样本。
- 明确要观察的函数、参数或网络字段，以及一个正控、一个同形负控。
- 预先写明证据不变量、停止点和 Hook 清理方式。

## 最小实验

1. **静态基线**
   - 记录脚本哈希、chunk/SourceMap 来源、候选函数和调用关系。
2. **运行时 baseline**
   - 不修改输入，观察一次正常调用和对应网络请求。
3. **Negative control**
   - 使用同类型无效值、固定错误签名或不触发目标函数的 UI 动作。
4. **Candidate probe**
   - 只改变一个输入，观察函数参数、返回结构和网络字段差分。
5. **Repeat**
   - 在新页面状态下复现一次，区分稳定算法与缓存、随机数、时间或会话依赖。
6. **Cleanup**
   - 移除 Hook、断点和临时覆盖，关闭调试上下文并确认页面恢复。

每个阶段生成 Evidence Envelope；原始脚本、SourceMap、调用栈和含秘密的 Network 内容按数据 policy 分类保存。

## 证据不变量

- 页面版本、脚本 SHA-256 和目标环境一致。
- 除候选变量外，账号、对象、请求体结构和调用顺序一致。
- 时间戳、nonce、随机数和会话字段被明确标识，不参与错误的稳定差分。
- Hook 只观察或最小替换目标函数，不改变无关控制流。
- Network 请求能通过时间、initiator 或自定义实验 ID 关联到函数调用。
- 浏览器预读、重试、Service Worker 和缓存请求不计作服务端独立命中。

## 数据边界

- 不在日志、Envelope、fixture 或 skill 中保存完整 Cookie、JWT、Secret、签名密钥或真实业务值。
- 若运行时不可避免观察到秘密，原值只进入 `evidence/restricted/`；正文记录类型、长度、来源阶段和不可逆指纹。
- 不 Hook 与当前 tactic 无关的登录、支付、第三方或个人数据流程。
- 不将可重放 token 保留为测试 fixture；验证完成后立即丢弃临时值。

## 停止条件

- 单变量差分已经证明参数来源或签名输入关系。
- 负控与候选无法区分，或脚本版本/会话发生变化。
- Hook 影响页面正常控制流、产生重复请求或触发状态操作。
- 观察到非测试用户数据、生产密钥或超出范围的第三方流量。
- 下一步需要绕过额外安全控制、扩大采集或持久化注入。

命中停止条件后保存最小证据、清理 Hook，并进入重路由、阻塞或评级；不得继续批量抓取。

## 回退和报告边界

`js.cdp` 不可用时：

- 回退到 `browser.interactive` 仅能观察 UI 和 Network。
- 可继续离线 JS/SourceMap 分析。
- Hook 参数、运行时 AST、精确调用栈和动态签名关系标记为未验证。

恢复 capability 后的第一步应是运行 baseline 与同形负控，不直接执行候选变更。

客户端存在敏感字段、隐藏路由或可复现算法只构成攻击面线索；必须结合服务端认证、授权、对象读取或状态影响证据才能升级漏洞结论。
