# Browser Validation

本 skill 使用 `browser.interactive` capability 验证真实 UI、登录态、选择器、租户/项目切换和浏览器特有行为。它服务于已选 tactic，不承担通用资产爬取或无目标浏览。

## 适用条件

- `RouteDecision` 的下一判别动作依赖真实浏览器语义。
- 需要确认 UI 是否暴露字段、对象选择器、角色入口或状态变化。
- 需要关联 UI 操作与 API 请求、截图和独立回读。
- 需要验证同源、Cookie、重定向、缓存、预读或渲染差异。

执行前读取 `dynamic-evidence.md`，并确认 `browser.interactive` 运行时可用。只有 HTTP fallback 时，不得声称已验证浏览器行为。

## 会话和对象准备

- 为不同账号、租户或角色使用独立 `browser_context`，禁止通过同一上下文切换身份形成污染。
- 先完成 self baseline，确认登录未过期、当前租户/项目正确、目标对象非空。
- 只使用授权测试账号、可回滚测试对象和最小分页。
- 认证材料进入 `evidence/restricted/`；Envelope 和日志只记录上下文别名。
- 记录浏览器版本类别和 capability provider 标识，不记录个人安装路径。

## 验证矩阵

1. **Baseline**
   - 正常账号通过真实 UI 完成预期动作。
   - 保存起始页面、选择器状态、关键请求 ID 和独立读取结果。
2. **Negative control**
   - 使用匿名、固定无效身份、随机对象或无权限测试账号。
   - 与候选探针保持相同路由、字段和动作，只改变一个授权变量。
3. **Candidate probe**
   - 按 tactic 执行一次最小交互。
   - 同时采集 UI 结果、网络请求和结构化响应差分。
4. **Readback**
   - 通过刷新、独立详情页、第二只读 API 或另一受控会话确认。
   - 排除浏览器缓存、乐观更新、预加载和 SPA fallback。
5. **Rollback**
   - 对状态动作立即精确恢复，并在新读取面确认恢复。

每一步生成独立 Evidence Envelope，共用 `candidate_id`、`tactic_id` 和实验 `request_id`。

## 采集要求

- 截图只截证明状态所需区域；含账号、token 或真实业务值时进入 restricted。
- 选择器记录语义和稳定属性，不依赖一次性 DOM 索引。
- 网络证据记录方法、route template、状态、关键字段类型和请求关联 ID。
- UI 文案只能证明浏览器显示；服务端状态必须通过网络或独立回读确认。
- 浏览器自动预读、Service Worker、缓存和扩展请求必须与用户触发请求分离。

## 状态动作

提交表单、上传、创建、删除、审批或调度前：

- 记录 `state_before`。
- 预先写明停止条件和精确回滚动作。
- 使用测试前缀和一个最小对象。
- 成功一次立即停止重复点击或批量操作。
- 遇到重复提交、未知 loading 状态或页面失去响应，先检查服务端状态，禁止盲目重试。

## 停止条件

- 正控失败或账号/租户上下文不确定。
- 负控与候选返回同形页面或同一公共响应。
- 页面暴露非测试用户、批量业务数据或不可逆功能。
- 已通过一次最小动作和独立回读证明影响。
- 回滚失败或无法判断状态是否已改变。
- 当前动作超出 tactic、scope 或副作用 policy。

## 回退与表述

`browser.interactive` 不可用时：

- 可使用 `cli.http` 验证协议可达性和静态差分。
- 把 UI 选择器、浏览器安全模型、缓存/预读和真实交互标记为未验证。
- 在 RouteDecision 中记录 capability 缺失和恢复后的第一个浏览器动作。

不得把 CLI 200、HTML 中存在按钮、前端路由字符串或截图中的提示直接写成服务端授权缺陷。
